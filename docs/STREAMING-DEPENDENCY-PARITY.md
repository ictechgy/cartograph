# Streaming dependency admission: validation boundary

This candidate changes only dependency admission in `RawIndexStoreReader`:
an eager owned tuple array becomes synchronous throwing `dependencies.forEach`.
Only `record`/`file` dependencies materialize a path; only admitted record contexts
materialize a module and record name. `kind` is read once per dependency and
`isSystem` once per admitted occurrence/date context. Every borrowed dependency
stays in the callback. Only owned strings and `Record` values are retained.

The baseline is commit `7a638355dee84ef01a2b6d7e4e60eea850554abf`, tree
`4241cb3c800b45a50f3d79db7511ce87374b2a72`. Its reader SHA-256 is
`a6a8567de5602146520d652885a3d186fdb46e23b06fb8501410cbea7390bea9`.
`Package.resolved` pins IndexStoreDB to
`64aa0b26913249c4e7c21d351a215fba02702003`.

At that revision the IndexStore sequence's `map` uses `compactMap` and synchronous
`forEach`; the throwing `forEach` callback accepts non-escapable dependency values.
The dependency string conversion produces owned Swift strings. The production
reader continues to traverse all units, sort records, load the bounded record
cache, convert/deduplicate occurrences, and finish all header-context checks.
None of those latter operations is changed by this patch.

## One-time native parity overlay

The two ordinary reader modes both call `RawIndexStoreReader`, so their existing
mutual comparisons are not independent evidence for this change. Instead,
`Scripts/prepare-streaming-dependency-parity.py` reads the exact historical blob
with `git show` and creates an independent eager reader in the test target. Its
only transformations are a type/error rename, an `@testable` import, and removal
of the duplicate `RawReadResult` declaration. A Python control reverses these
transformations and requires byte equality with the pinned blob.

Preparation belongs only in the disposable coverage checkout for the original
`perf/stream-index-dependencies` PR, before its existing Build/Test steps. It is
not a permanent additional build or a strategy switch in the product. The CI
step must admit the same-repository PR's exact baseline before preparation; a
different base SHA fails rather than silently skipping the check. Ordinary
coverage and all other jobs stay unconditional and otherwise unchanged.

After the pinned commit object is available locally, run:

```sh
python3 Scripts/verify-streaming-dependency-parity.py
parity_temp="$(cd "$RUNNER_TEMP" && pwd -P)"
python3 Scripts/prepare-streaming-dependency-parity.py \
  --evidence "$parity_temp/streaming-dependency-parity"
# Continue the job's existing Build and Scripts/coverage.sh steps.
```

The preparation command does not invoke Swift or fetch anything. It refuses:

- A reader differing from the exact dependency-only baseline transformation
- Changed original fixture-test bytes or a different IndexStoreDB pin
- Pre-existing generated test files, symlinked inputs/destinations, or reused evidence

It changes exactly six test paths: the two original fixture suites plus four
generated Swift files (assertions, uninstrumented baseline, counted baseline,
counted candidate). It verifies every `Sources` file and both Package files are
unchanged. The fresh evidence directory must be outside the checkout. It retains
all generated bytes, their hashes, original fixture hashes, the generator/template
hashes, and the before/after-verified production hashes. `prepared_not_executed`
is not a native pass. Preserve that evidence alongside the native coverage result.
Do not reuse a partially prepared checkout after a failed step.

## Exact assertions on existing real fixtures

Only constructor/type references in `RawIndexStoreReaderTests.swift` and
`HeaderRecordAdmissionTests.swift` are redirected to test-only parity wrappers.
Their test bodies, compiler fixture builders, authored expected facts, and
production-provider return/error values remain in place. The original eager
reader and the unchanged production candidate read each same fixture state.
No fixture rebuild occurs between those reads. Store file bytes and modification
dates are compared before and after them.

Each successful comparison checks:

- Ordered occurrences and ordered relations, including every symbol's USR,
  name, kind, subkind, properties and language; all roles/provider values; and
  every location path, timestamp, module, system flag, line and UTF-8 column
- Exact latest-date and oldest-date dictionaries and admitted-header arrays
- Complete `IndexSnapshot` equality and sorted-key encoded bytes for all four
  external-symbol/self-reference option combinations, plus `sourceFreshnessDates`
- Exact ordered tracked-path callback inputs/results, including rejected paths
- Every existing cache callback event `(reader count, queue count)`, including
  its total count, not merely the maximum; both counts remain bounded by 64

No result array is sorted or collapsed into a set to make the comparison pass.
Successful parity compares full multiplicity and order. Error cases must agree
on failure and their localized cause; they must not return partial facts.

The retained real fixture matrix covers:

- Relative and symlinked Swift paths, two module contexts, Swift module fallback,
  unrequested paths, an empty store, and an occurrence-free Swift record
- A partial rebuild of only one shared-source target: latest and oldest dates
  straddle the source edit and freshness uses the oldest observed context
- Objective-C source/header records and an SDK file-only dependency
- Seventy shared Swift records: complete two-module facts, cache-open traces,
  and the existing bounded-reader/queue assertions
- Shared headers with duplicate contexts and alternate calls for the same USR;
  outside/excluded headers; a system-marked context; mixed record/file-only units
- Disabled/deleted header admission and deleted Swift-source date preservation
- An unreadable unrelated unit, an unreadable requested record, and one corrupt
  header context: full reads fail instead of returning a partial success

## Metadata access evidence, not an allocation benchmark

The production reader and independent eager oracle are uninstrumented. Two
additional generated test-only copies count the existing dependency getter/string
sites. Their complete results/errors must match their uninstrumented counterparts.
They introduce no product API, environment switch, protocol, or persistent counter.

For a successful complete read, let `D` be all dependencies, `F` record/file
dependencies, `T` admitted occurrence/date contexts, and `A` admitted record
contexts. The native assertions require matching `D/F/T/A` across both copies and:

| Dependency access | Eager | Streaming |
| --- | ---: | ---: |
| kind / dependency callback | D | D |
| filePath.string | D | F |
| moduleName.string | D | A |
| name.string | D | A |
| isSystem | D | T |

Thus the three owned-string conversions change from `3D` to `F + 2A` and the
temporary dependency-tuple array is absent. This counts executed access/conversion
sites, not malloc calls or saved bytes. For an error inside a unit, eager admission
has already copied that unit's dependencies; the success-only count formula does
not claim equal partial enumeration on failure. Error and tracked/cache-trace
parity remain required.

Each successful pair emits one test-only `cartograph-streaming-dependency-parity-v1`
line with sorted-key JSON: both integer counter records and both cache-open event
counts. It contains no paths, symbol names, or pass flag. Preserve the ordinary
coverage log; these records are not produced by product code. Acceptance comes
from the actual native test result, never from the presence of a count record.

## One fixed native pilot

`Scripts/pilot-dependency-admission.py` reuses the existing public-project oracle,
process capture and phase parser. It admits the already-built candidate release
and builds the exact pinned main revision above in a fresh, separate release
scratch. The compiler, resolved dependencies and build arguments must agree;
the product input maps may differ only at `RawIndexStoreReader.swift`. Source,
binary and shared project/index bytes are checked before capture and afterward.
Baseline setup and its full cost are retained, with a 1,500-second setup bound.

The fixed capture is 22 processes: one baseline/candidate pair for each ambiguous,
missing and mixed-duplicate query; then baseline/candidate/candidate/baseline twice
for the found query with phase diagnostics on, and the same eight runs with them
off. Each command has 45 seconds and a 1 MiB stream cap; the complete capture and
its final checks have 300 seconds. Every sample is retained. Full stdout, exit
and ordinary stderr must match, removing only the recognized phase record, and
the frozen source-authored answer oracle must pass before timings are summarized.

The native steps are limited to the same-repository
`perf/stream-index-dependencies` pull request and explicitly refuse base drift.
The existing 35-minute comparison-job bound remains. Postmerge ordinary CI still
runs, but this one-off baseline build and pilot do not repeat automatically.
Global SDK and dependency caches are not flushed; there is no cold-cache claim.
Phase timings are instrumented wall estimates. The diagnostic-enabled and disabled
samples, CPU and RSS remain separate; there is no trimming, adaptive retry or
general performance conclusion. A mixed or negative result can reject the candidate.
