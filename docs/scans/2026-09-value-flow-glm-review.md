# 값 흐름 PR #69 — GLM 리뷰 검증

전체 기능 diff(`8b677eb`, 패킷 SHA-256 접두사 `9df8a7b01ec5`)를 GLM high로 검토했다.
명시적 캡처 수정은 별도 GLM low 패킷(`94cc692fa594`)으로 검토했다. 모두 packet-ask로 선택·
정리한 코드만 전달했으며, 정적 모델 응답을 직접 실행하거나 검증 완료의 근거로 대신하지 않았다.

## 전체 diff 지적

| 지적 | 판정과 처리 |
|---|---|
| 인자 위치만으로 리터럴 타입 차용 | 기본 인자가 생략된 호출의 타입 차용을 막았다. 인자 수와 제공된 라벨이 맞을 때만 위치 타입을 사용한다. GLM의 인자 재배열 예제는 Swift 컴파일 오류지만, 기본 인자 생략 문제는 유효하다. variadic·autoclosure는 현재 모델에서 미지원임을 표시한다. |
| 반복 extension의 소유자 혼합 | 각 extension의 소스 ID를 보존하고 실제 `.extends` 근거로 nominal owner에 연결한다. 서로 다른 extension과 누락된 두 번째 근거를 회귀로 검증한다. |
| 결합 단계의 반복 선형 탐색 | 심볼 위치·부모·파일, extension 위치, 참조의 소스/위치를 한 번 색인한다. 8,000개 선언과 20,000개 잡음 심볼에서 이전 탐색을 복원하면 약 37초로 시간 상한 검사가 실패했고, 수정 상태는 약 0.14초였다. 전체 프로그램 처리 시간의 순위로 일반화하지 않는다. 신선한 동적 Swift 사실이 없으면 브리지 값 분석을 생략한다. |
| SDK 이름이 조회 후보에 섞임 | 오탐. `GraphBuilder.Options.includeExternal` 기본값은 false이며 `isExternal` 심볼을 이미 제외한다. 같은 이름의 SDK 심볼을 포함한 서비스 회귀 테스트도 로컬 함수만 찾는다. 자기 참조 간선은 이름 조회의 후보를 늘리지 않는다. |
| Unicode 정규화 형태를 확정 문자열로 합침 | Swift에서 동등해도 UTF-8이 다르면 `unicode-normalization` 미상 이유를 보존한다. 값 출력과 브리지 승격 모두 하나의 확정 이름으로 읽히지 않는다. |
| 두 번째 읽기 실패로 브리지 사실 소실 | 첫 스캔에서 읽은 소스를 값 분석과 재스캔에 재사용한다. 후속 읽기가 실패해도 저장한 입력으로 분석하는 회귀 테스트를 추가했다. |

외부 심볼 메타데이터는 실제 호출 대상과 리터럴 변환의 증거로 계속 필요하다. 이를 모두 지우는
대신 반복 전체 순회를 제거했다. 파싱을 포함한 전체 분석이 solver 예산만으로 일정 시간에 끝난다는
주장은 하지 않는다.

## 명시적 캡처 수정과 후속 지적

직접 만든 실제 Swift 반례에서 `[value]` 캡처가 실행에서는 `before`, 분석에서는 `after`로
잘못 나왔다. 생성 시점의 값을 복사하도록 수정했고 `[snapshot = value]` 별칭도 검증했다.
weak·unowned 소유권은 미상으로 유지한다. 이 실행 하네스를 CI에도 추가했다.

- GLM의 이중 읽기 지적은 오탐이다. `readMemory`는 reference atom만 역참조하고 문자열·객체·함수 등
  비주소 값은 그대로 전달한다. 값/별칭 캡처의 서비스 테스트와 실제 실행 모두 생성 시점 값을 유지한다.
- closure parameter의 내부 이름 누락 지적도 오탐이다. `closureParameters`가 이미 `secondName`을
  보존하고 `createParameters`가 그 이름을 바인딩한다.
- 문자열 리터럴 캡처가 항상 미상이라는 지적도 오탐이다. 실행 전 literal binder가 입증한 문맥을
  `.literal`로 바꾼다. `[snapshot = "literal"]` 서비스 회귀로 확인했다.

CI에 새로 연결한 실행 하네스는 Xcode의 `out` 경로만 가정하던 오류를 드러냈다. 일반 SwiftPM의
`debug/index/store`도 찾고 실행 파일은 `swift build --show-bin-path`로 찾도록 수정했다.

## 수정분 재검토

`8b677eb..6960175` 수정분과 누락됐던 기반 코드 문맥을 GLM low로 다시 검토했다
(패킷 SHA-256 접두사 `379e5a6c4743`). 결합·색인·인자·정규화·경로 수정이 반영됐다는 응답을 받았다.
추가 지적은 다음과 같이 판단했다.

- 파일별 인덱스 시각이 없을 때 값 분석을 실행하라는 제안은 채택하지 않았다. 이전에도
  `freshPaths`와 literal binder의 필수 신선도 조건 때문에 확정 이름을 만들 수 없었다. 미상 날짜를
  신선함으로 대체하지 않으며, 기존 동적 사실은 그대로 보존한다.
- 캐시 누락을 파일 읽기 실패라고 부르는 부분은 개선했다. 내부 인자를 `sourceSnapshot`으로
  명명하고 `uncaptured-value-flow-sources`로 따로 센다. 이 입력은 일부 prefetch가 아니라
  첫 읽기의 고정 스냅샷이므로 후속 파일을 읽어 서로 다른 시점의 입력을 섞지 않는다.
- 서로 다른 `A`/`B`에도 정규화 경고가 붙는다는 관찰은 오탐이다. Swift String을 키로 그룹을 나눈
  후 같은 그룹 안의 UTF-8만 비교한다. 두 가능한 값과 빈 미상 이유를 직접 단언하는 테스트를 추가했다.
- class의 `mutating` 메서드는 Swift에서 유효한 형태가 아니다. 합법적인 mutating 값 타입 메서드는
  extension 안에서도 일관되게 미지원으로 남겨, 참조형으로 잘못 해석하지 않는다.
