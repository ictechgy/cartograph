# Bridge facts in the wild: 14 public Flutter and React Native repositories (2026-09-05)

What `cartograph bridges` sees on the Swift and Objective-C side of public plugins, measured to
answer three questions: how much of the ecosystem still crosses the language boundary with string
channels, what the scanner attributes with confidence versus what it has to count as a limitation,
and which real code shapes the scanner had never seen.

## Method

Each repository was fetched at the pinned commit in `Scripts/scan-public-plugins.sh` (full SHAs in
the script; short ones in the table) and scanned with the exact command in that script,
`cartograph bridges --project <repo> --format json --exclude '**/example/**' '**/.cartograph-scan/**'`,
built from cartograph commit `37411f8` (the scanner changes described below, unreleased as of
0.5.3). All 14 scans exited 0. No Flutter SDK was involved: `bridges` walks the
sources with SwiftSyntax and reads `.m` files as text, and only needs an index store to attach USRs.
A dummy SwiftPM target at each repository root provided an index store, so every fact here has
`missing-handler-usrs` and no USR; that column is omitted. `example/` directories were excluded from
both the file counts and the facts. "Pigeon Swift files" counts files containing the generator's
`Autogenerated from Pigeon` line, which is the direct measure of Pigeon output. The
`BasicMessageChannel` column, counted by the scanner, is the total of message-channel constructors
whatever wrote them; it is a noisy proxy for generated code, not a measurement of it.

The Dart side was not scanned (dartograph does that; see isthmus).

"attributed", "inferred" and "channel null" partition the `method-handle` column and sum to it.
"attributed": the handler's channel came from something the code states — for Flutter a
registration call (`addMethodCallDelegate`, or `setMethodCallHandler` with a closure or a method
reference), for React Native the `RCT_EXPORT_*` or `@objc(Name)` declaration. "inferred": the
fallback where a file constructs exactly one channel and a `FlutterMethodCall` handler is attributed
to it because its registration lives in another file. "channel null": a handler the scanner saw but
could attach to no channel. "dynamic" is orthogonal: it counts facts of any kind whose channel or
method is not a literal, so a handler can be both attributed and dynamic (flutterfire has one).

## What the numbers say

**The first-party ecosystem has left string channels.** `flutter/packages` has 703
`BasicMessageChannel` constructors against a single `FlutterMethodChannel` registration. Only 15
files carry the Pigeon header, so most of those constructors are in files this scan cannot prove
were generated; what it can say is that the message-channel API, not the method-channel API, is
where first-party code crosses the boundary. flutterfire is mid-migration (150 message-channel
constructors, 4 method-channel registrations left). For these, the join isthmus performs today has nothing to join; the exchange format needs a
message-channel fact kind before it can cover them, and the scanner counts them as
`unscanned-message-channels` so the gap is visible rather than silent.

**The community plugin tier still uses string channels, mostly in one shape.** plus_plugins,
mobile_scanner, flutter_secure_storage and flutter_local_notifications cross the boundary with
`FlutterMethodChannel` and a `FlutterPlugin.handle(_:result:)` method; audioplayers registers one
channel by method reference and delegates the other through a second hop (see below). That shape is
exactly what an agent-driven cleanup would misjudge: the handler's `case "…"` arms have no Swift
caller.

**Half of the popular plugins are invisible to this tool.** permission-handler, geolocator,
just_audio and sqflite implement iOS in Objective-C. `cartograph` reports them as
`objective-c-sources` and finds no facts. Any claim about coverage has to say this first.

**Nitro and JSI modules produce no string facts, correctly.** react-native-vision-camera has 429
Swift files and zero bridge facts because it does not use `RCT_EXPORT_*` or `@objc(Name)`; the
older React Native modules (device-info, webview) still do, all of it in `.m` files, which means
no USR and therefore no retention round-trip.

## What the scan found in the scanner

Three code shapes the corpus had never contained, all fixed and pinned by unit tests in the same
change as this report:

1. **Delegate registration is a fact, not a guess.** `registrar.addMethodCallDelegate(instance,
   channel: c)` names the type whose `handle(_:result:)` receives the channel. Before this scan the
   scanner attributed those handlers by the "single channel in the file" heuristic and counted them
   as inferred: 52 of 110 handlers in the first pass of this scan. After: 14, all in
   flutter_local_notifications, whose registration happens in another file. The attribution is keyed
   by the full type name and requires the `handle(_:result:)` signature; a type registered on two
   channels gets `null`, not a guess.
2. **Handlers passed as method references.** audioplayers registers with
   `channel.setMethodCallHandler(handleGlobalMethodCall)`. The referenced method is the handler and
   its arms belong to that channel.
3. **`setMethodCallHandler(nil)` is an unregistration**, and was being emitted as a
   `channel-register` fact.

One shape remains open and is counted honestly: audioplayers' `handle(_:result:)` forwards the call
to `handleAsync(_:result:)` inside a `Task`, and its 23 arms live there. Following one hop of
`call` through a local function call is the next scanner change if a second plugin shows the shape.

## Limits of this scan

Fourteen repositories chosen by the author, not sampled. Swift side only. No USRs, so nothing here
tests the retention round-trip; the corpus and the isthmus `plus_plugins` gate do that. Dart-side
call counts, which would say how many of these handlers anything actually invokes, need dartograph
and were out of reach in the authoring environment. The scanner used is a development build; the
numbers should be re-run and this file amended once that build ships as a release.
