# External-project comparison protocol

Protocol fixed on 2026-09-15 before inspecting comparison outputs. This is a bounded
pilot, not a ranking of all Swift tools or a productivity study of application teams.

## Inputs and selection

- Cartograph 0.13.0 (installed release), Periphery OSS 3.8.0 (installed release),
  the installed Swift 6.4 SourceKit-LSP, and ripgrep.
- Public projects: Alamofire `bda9ed57d72988a3a2ada33d824583541f86eac6`,
  Kingfisher `ab1c1de54a1ce1adfe1733c7195056a153029d3a`, and Swift Argument Parser
  `93c68882a28d9c82cd87be0acb7d76e35494b9b5`.
- These are maintained libraries, not three complete applications. Results concern
  their macOS production sources. External clients and inactive platform branches
  are outside the ground truth. Public APIs must be retained in dead-code scans.
- Fresh local clones are built with the installed compiler. Both index consumers
  receive the same `.build/out` index. Build preparation is measured separately.
- Independent read-only readers select two declarations per project from recent
  production changes without seeing Cartograph, Periphery, or LSP results. They
  enumerate immediate consumer declarations and exact source references. Repeated
  references inside one consumer count once. Historical provenance motivates tasks;
  this does not replay complete historical bug fixes.

## Outcomes

1. **Impact review:** compare immediate consumers from Cartograph, SourceKit-LSP
   references/call hierarchy, and literal whole-word retrieval. Source inspection
   establishes the oracle first; compiler mutation diagnostics validate suitable
   targets independently. Declarations, callsites, and textual hits must not be
   conflated. Explicit source/semantic disagreements are adjudicated and retained.
2. **Unused code:** run both detectors on matching production scope with public and
   Objective-C retention enabled. Report total output separately from adjudicated
   findings. Align optional unrelated checks for a common-task scan; also record
   Periphery's additional assign-only diagnostics. A lower finding count is not
   higher accuracy. Disagreements require source/build evidence, and unresolved
   cases remain unscored. No automatic deletions.
3. **Agent-assisted review:** fresh agents with the same role/model and identical
   task/source access receive either ordinary search or ordinary search plus
   Cartograph evidence. Both arms may inspect source. Gold answers are withheld.
   Report bounded task correctness and elapsed time; do not invent token/cost data
   unavailable from the runner or generalize a small sample to all coding agents.
   LSP retrieval provides an additional semantic baseline; a search-only agent
   comparison must not be presented as a comparison against a full IDE workflow.

Use three serial scan/query samples on unchanged inputs and record tool failures,
output equality, initialization cost, and result sizes. Warm query latency excludes
session preparation, which must be shown separately. No unrelated builds during
timed samples. SourceKit-LSP readiness must be synchronized before scoring empty
results. Unsupported tools or unavailable authenticated products are `not run`,
never zero recall. Current Periphery commercial/beta documentation is a separate
feature comparison, not the measured OSS binary.

## Decision rule

Prefer improvements supported by observed missed consumers, misleading evidence,
unnecessary review candidates, or setup failures. If ordinary search or LSP solves
these tasks equally well, report no demonstrated accuracy advantage. This pilot
does not justify universal dependency recall, safe deletion, test omission,
competitive speed ratios between different workloads, or adoption claims.

Preserve pinned inputs, prompts, raw outputs, timings, oracle revisions, commands,
and machine-readable scores. Published artifacts use project-relative paths.

## Recorded setup corrections and limits

- The initial harness joined two `--include` values with a comma. Cartograph
  rejected that scope; those Argument Parser runs are excluded. The accepted
  harness passes separate arguments. Periphery's target exclusions alone left
  two tool-extension findings; explicit index exclusions fixed the scope before
  accepted counts. Original outputs remain in the local evidence directory.
- SourceKit-LSP did not produce references when background indexing was disabled,
  even after `workspace/synchronize(index: true)`. Its normal background indexing
  resolved this. The accepted LSP runs use its own prepared index on the same
  pinned sources; only Cartograph/Periphery share `.build/out`. Initial empty
  responses are setup failures, not measured misses.
- Accepted query latency samples were repeated serially after the agent trials ended.
  Filesystem caches were not dropped. Preparation is separate from warm requests.
- Agents used the same `explore` role, `gpt-5.6-luna`, low reasoning, fresh context,
  and read-only tasks. There was one trial per arm per project, two questions per
  trial. This measures consumer review, not successful code edits or application
  behavior. The repository preserves structured final answers and clock readings;
  complete native tool transcripts and token/cost accounting are not exported.
- Compiler mutations use separate build directories and restore original source
  bytes and mtimes. A compiler can stop before diagnosing every known reference;
  undiagnosed witnesses remain explicitly listed rather than being called passes.
- After the frozen pilot, an additional `query` CLI/MCP measurement checks whether
  the narrower existing command changes the consumer set or latency conclusion.
  This is labelled supplemental and does not revise the assigned agent prompts,
  original task selection, or primary scores.
